附件中代码中的 CompactLeafListEncoder 设计是失败的，因为 json 会优先在父类匹配原生类型的编码，不会执行子类的 default 函数。
关键证据在于 json_test(Inheritance).py 即便用原生类型的继承，也不会触发 自定义类，
而包装类型 json_test(wrapper).py 则可以触发自定义类。
现在我需要设计一套 json <-> _CASE_TYPE 互转的系统，要求仅函基础类型的数组采用压缩json格式（不换行）。并且能够保存、读取自定义类型如 ListNode到json文件。
请结合已有工程经验分析如下方案的可行性：
1. 保持原生 json，自定义类型保存前强制转为 list，读取时根据调用函数自动转换。
   - 优点：实现容易；
   - 缺点：json文件不能直观反映自定义类型，如果不indent，那么长数组会疯狂换行不便人工阅读。
2. 完全自定义类型：
   2.1 对于叶子层数组，最好是限制数组元素除了 None 只有一种类型，包装为自定义的 array 类型，并以 array 作为中间格式进行序列化和反序列。
   2.2 对于自定义类型，显然兼容。
   - 优点：json文件直观反映自定义类型；
   - 缺点：使用复杂；读取 array 后还需要解包转换为原生数组。
3. 单向序列化：
   3.1 对于叶子层数组，最好是限制数组元素除了 None 只有一种类型，包装为自定义的 array 类型，但是转换后的格式与常规数组不indent时保持一致。如此可仅以实现单向序列化，即只支持 array 转 json，但 json 读取时会误认为是普通数组。
   3.2 对于自定义类型，务必要能双向序列化。
   - 优点：json文件直观反映自定义类型；
   - 缺点：实现复杂（原生 json 可能无法实现 3.1，可能需要第三方库）。
4. 使用第三方库：
   - 使得叶子层数组不换行（不 indent），其余结构保持缩进。
   - 要能兼容自定义类型。
