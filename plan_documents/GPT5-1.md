## 🧠 Phase 1：RAG 驱动的测试用例生成（当前核心目标）

目标：
将 **题目 + 代码 + 相关文档** 自动组合，提升大模型生成测试用例的质量与稳定性。

---

### 1️⃣ 代码分片（Code Chunking）

对学生代码或参考代码进行结构化切分：

**分片策略（多策略融合）**

* 按函数 / 类划分（优先）
* 按缩进块划分（AST fallback）
* 按特殊符号划分：

  * `{}`（C/C++ 风格）
  * 空行（逻辑块）
* 保证：

  * 单 chunk 语义完整
  * 长度适中（适配 embedding）

---

### 2️⃣ 代码语义增强（Chunk Annotation）

对每个 chunk 自动生成说明：

* 使用 **轻量模型**（如 GPT-3.5）生成：

  * 功能描述
  * 输入输出说明
  * 边界条件提示

示例：

```python
def deleteDuplicates(self, head):
```

→ 描述：

> 删除排序链表中所有重复元素，仅保留不重复节点（类似 LeetCode 82）

---

### 3️⃣ 依赖关系建模（Dependency Graph）

> ⚠️ 这里建议你改名：
> **“依赖概率” → “语义依赖权重（Semantic Dependency Weight）”**

构建一个**有向加权图**：

```
Node = code chunk
Edge = dependency
Weight = relevance score
```

#### 定义：

* `W(A → B)`：使用 A 时，需要 B 的概率

#### 示例：

```
A = deleteDuplicates
B = ListNode definition

W(A→B) = 0.95
W(B→A) = 0.2
```

---

### 4️⃣ 检索策略（核心 RAG 逻辑）

当用户输入：

```
题目 + 学生代码
```

执行：

#### Step 1：Embedding 检索

* 检索 Top-K chunks

#### Step 2：依赖扩展（关键创新点 ⭐）

* 根据依赖图扩展：

```
Top-K → 补充高 W(A→B) 的节点
```

#### Step 3：上下文组装

最终 prompt：

```
[题目描述]
[学生代码]
[相关 chunk（含描述）]
[必要依赖 chunk]
```

### 5️⃣ 动态权重更新（在线学习机制）

你原来的思路是对的，这里帮你工程化👇

#### 数据来源（非隐私）：

* 用户是否追加上下文
* 模型是否修正答案
* 错误类型（解析失败 / 类型错误 / 逻辑错误）

#### 更新规则（简化版）：

```
若：
仅提供 A → 错误
提供 A + B → 正确

则：
W(A→B) += α
```

建议：

* 初期用简单规则（避免复杂 ML）
* 后期再引入学习算法

### 6️⃣ 执行反馈闭环（Execution Feedback Loop）

这是你方案里**最有价值的一点**，建议重点写：

#### 流程：

```
生成测试用例 → 执行 → 收集结果 → 反馈给 RAG
```

#### 反馈内容：

* 是否运行成功
* 错误类型（Runtime / Type / Infinite Loop）
* 输出 vs expected 差异

#### 用途：

* 优化：

  * chunk 权重
  * prompt 结构
  * 测试生成策略
